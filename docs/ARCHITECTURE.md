# 架构与实施边界

## 模块
C++20 / CMake / Win32 / D3D11 / Dear ImGui。src/core.* 负责模型、UTC+8 计划展开、SQLite 和有界日志；src/ndi.* 负责 SDK 动态加载、发现、预览/监听及测试源；src/media.* 是接收、时间映射、滤镜、编码和封装链路；src/manager.* 管理每路工作进程；src/ui.cpp 是时间线和编辑界面。

主进程不承担录制编码。每路复用同一 exe 的 --worker 模式，通过命名共享内存交换停止请求、结束时间、心跳和状态。工作进程加入 kill-on-close Job Object，主进程消失时不会遗留无限运行的录制进程。
状态使用单写者序列计数快照，控制字段采用 Interlocked 操作。工作配置是独立 JSON 快照，录制中编辑不修改快照。

## 媒体链路
NDI receiver → 原时间码与像素/样本复制 → 有限接收队列 → 公共时间映射 → 去隔行/缩放 → 有限视频与音频缓存 → 编码 → 分段封装。
音频和视频映射使用同一个起点。NDI timecode 无效时使用 SDK timestamp，再降级到到达时间。源时钟明显跳变时共同重建映射并记日志。
正常录制使用有限时长抖动缓冲；音频按时间位置拼接，轻微时钟漂移受限补偿。无损模式跳过增益、缩放和漂移重采样。

1080i50 的交织帧进入 bwdif send_field，输出 50 个逐行帧。滤镜输出的 time_base 必须显式换算为微秒。
SDK best 模式可能返回 1920×540 顶/底场；无损分支验证场序及时间间隔后配对为 1920×1080。P216 解交织为 16 位 YUV422，PA16 额外保留 alpha。

视频和音频分别检测缺失并补黑/静音。输出计时不依赖窗口刷新或系统显示器。
每个新片段从关键帧开始，编码器保持会话时间轴。H.264 MP4 延迟写入初始 moov 并碎片化，处理 AAC priming；封装不保证突然断电后最后片段完整。

## 有界资源与失败
- NDI 接收队列：128 MB、128 项、500 ms 上限，优先释放旧数据。
- 滤镜后视频队列：按真实像素字节数限制到 128 MB，最多 64 帧。
- 音频块队列：最多 128 项；源输入采样块大小有验证。
- 预览：单份缩小图，最多 320×640；监听最多 4 个 waveOut 缓冲。
- 日志：每进程最多 2048 条等待写入，溢出计数；单文件 16 MB 轮转，按时间和总容量回收日志。
- 编码持续落后超过 2 秒时停止该工作进程；启动阶段留有限追赶窗口。
- 心跳 30 秒无更新时终止无响应工作进程；连续失败最多自动重试 3 次（2/4/8 秒退避），第四次失败需人工恢复；连续正常录制 30 秒或正常结束重置计数。
- 磁盘安全余量不足不自动重试，不删除录像，不转存其他目录。

SQLite 使用 WAL、FULL 同步和事务配置保存；录像历史独立按片段和异常区间记录。
GUI 的文件选择对话框运行嵌套消息循环时仍通过 WM_TIMER 调度计划。

## 当前边界
首轮针对 SDR Full NDI 1080i50/1080p60，非 NDI Advanced 压缩码流透传。H.265 不包含在本版。
每路音画同步与跨设备帧同步不同；本版不提供多机 genlock。
无损校验摘要覆盖进入编码器的像素与选择的两路音频样本；不能证明输入源本身未压缩，也不能代替掉帧测试。
四路 24/72 小时、断电恢复、真实广播设备场序和未登录运行不属于本轮已通过项。未登录运行不支持，不安装 Windows 服务。
