# 验收记录（0.1 开发预览版）

最新回归日期：2026-09-23。Windows x64，本机 NDI Runtime 与 vendor FFmpeg。发送端为程序内置 Full NDI 测试源，实际经 NDI SDK 接收、编码、写盘；本轮测试源的每秒脉冲采用变化的秒内相位，避免严格周期信号掩盖整秒错位。

## 本轮修复

- 停用、删除、跳过当前计划后能够结束对应需求；手动需求仍有效时继续录制。正常到点保留抖动缓冲排空，停止期间重新出现需求会在旧工作进程退出后启动新任务。
- 连续失败允许三次自动重试；正常完成或连续健康录制 30 秒后清零。陈旧心跳不会被视为健康恢复，旧错误不再遮盖新状态。
- 新任务使用当前存储设置，运行中任务按自己的路径及安全余量保护。
- 监听跟随声道对、增益和当前任务参数快照；录制中编辑来源不会把监听切到另一来源。无信号时也可关闭监听。
- 无首帧时可取消地等待真实规格；到期正常结束，首帧晚到记录缺失区间，不再默认建立 1080p50 任务。
- 同步检查增加一对一配对、未匹配统计和最少样本要求。复用像素转换上下文，直接逐行计算无损摘要，减少整帧分配和复制。

- python tools/recovery-smoke.py
- python tools/ui-smoke.py
- python tools/safety-smoke.py

测试使用 build 下独立配置、录像和报告。不要并行运行共享 test-data/last-test.json 的录制脚本；运行 GUI 测试前退出正式程序以免单实例保护拦截。长时间压力测试需使用实际硬件并预留存储空间。

| 指标（两轮平均） | 监测关闭 | 监测开启 |

## 2026-10-02：长期黑场保护、监测窗口和现场诊断

版本 v20261002；本机 Windows 10，界面按用户约定仅测 100%。没有完成真实 24 小时或 Windows 11 测试，现场黑场根因尚待日志确认。

- 发现并修复时钟校正盲区：原逻辑画面过期 300 ms 即补黑，但需偏差超过 2 s 才校正。新增视频时钟持续偏差校正（超过 100 ms 且持续 2 s），音视频共用校正量；日志记录校正与补黑时的时间戳。新鲜输入仍连续补黑超过 10 s 会交由原工作进程恢复策略处理。
- 真实 NDI 源在第 10 秒时间码回退 600 ms：22 秒 H.264 录制正常结束，1320 帧，补黑 121 帧约 2.02 秒，后续恢复，最后 5 秒 300/300 帧非黑。该故障注入会产生短暂缺口，不宣称无缝恢复。证据：build/clock-recovery/result.json。验证脚本使用实际合成源最低非黑亮度修正了检查阈值（源正常暗画面的缩略亮度可低至 6，不能把 <=10 都认成黑场）。
- 实际媒体回归六项通过：p60、i50、lossless_i50、lapse、lapse_sparse、70 秒 segments_outage。分段输出的开始/结束日期时间文件名、历史路径和 FFV1 校验文件一致。
- core/manager/sync-checker 三组通过。新增 24 小时虚拟采样回归检查最后 60 秒差量仍为固定窗口，以及 SQLite 在线快照、历史改名、时间码回退校正。
- 100% UI 的拖动、缩放、导航、监听音量、自动跟随五项通过；手动浏览后 followNow=false，默认跟随时视窗随实际时间推进。
- 发布目录的 PowerShell 5.1 诊断脚本完成带程序运行的 33 秒采样测试（两次采样、有进程数据及速率、在线数据库快照、无采集错误）；停止命令与最终 finished.json 通过。修正了继承不同 PowerShell 模块路径时 Get-FileHash 不可用的问题，改用 .NET SHA256，不需安装模块。
