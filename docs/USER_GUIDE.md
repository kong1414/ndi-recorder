## 1. 安装与启动

1. 从发布包 `ndi-recorder-vYYYYMMDD-windows-x64.zip` **完整解压**到一个可写目录（不要只解压 exe，同目录的 DLL 是运行必需的）。
2. 双击 `ndi-recorder.exe` 启动。程序需要 Windows 10 / 11 x64 和 NDI 运行环境。
3. 首次启动后，程序在 exe 同目录创建 `data/recorder.db`（配置与历史）和 `recordings/`（默认录像目录）。

升级版本：退出旧程序 → 备份 `data/` 目录 → 用新包的程序和 DLL 覆盖原目录 → 启动。不要混用新旧 DLL。

## 2. 快速上手：第一次录制

1. 点击顶部 **「+ 添加来源」**：从自动发现的列表中选择 NDI 源，或粘贴完整源名（形如 `HOST (Camera 1)`）。
   - 列表会自动更新；找不到源时，到「基础设置」填写逗号分隔的额外发现 IP 后重新发现。该 IP 仅用于发现提示，不是任意 NDI 推流地址。
2. 点击该路的 **「设置」**，确认录制参数（编码、码率、分段等，见下文），保存。
3. 点击 **「立即录制」** 开始手动录制；再次点击 **「结束手动」** 停止。
4. 录制条目出现在时间轴下半部，结束后变为绿色「已完成」。双击该色块可直接打开文件。

**首次使用请先录一小段并播放验证**，重点检查声道、场序、音画同步、输出码率和磁盘写入速度是否满足要求。

## 3. 主界面导览

- **顶部工具栏**：添加来源、基础设置、录制历史、导出/导入配置、回到现在、自动跟随、小时/日/周视图、日期跳转。
- **每路一行**：左侧为固定 16:9 预览（非 16:9 源等比缩放留黑边）和两条音频电平；中间为控制按钮；右侧为合并时间轴。
- **控制按钮**（自上而下）：「立即录制 / 监听」「计划… / 音频 / 监测」「计划启用 / 设置 / 删除」。监听中的按钮显示绿色。
- **底部**：时间导航滑块；监听音量区；存储可用/总容量、预计可录时长（有损估算）、系统 CPU/内存、主进程内存、近 5 秒文件写入速度、网卡收发与链路状态。
- 鼠标悬停在预览或控制区时，滚轮上下滚动通道列表。

## 4. 通道管理

### 添加与选择来源

添加来源时可从发现列表选择，或粘贴完整源名。每路的预览与录制使用**独立接收器**，因此发送端和网络需要承担相应流量。空闲预览请求 SDK 最低带宽流，默认最多 15 fps；源是否提供低规格流由发送端决定，不等同于 NDI HX 转码。

### 通道设置参数

| 参数 | 说明 |
|---|---|
| 每段时长（分钟） | 自动切割长度，默认 60，范围 1–1440。分段在关键帧处完成，实际可能略长 |
| 输出编码 | H.264 / MP4 或 FFV1 / MKV 无损 |
| 目标码率 | H.264 默认 20 Mbps |
| 分辨率 | 宽和高均设为 0 表示跟随源；自定义值必须为偶数 |
| 帧率 | 0 表示逐行源跟随源帧率、隔行源双场去隔行（1080i50 → 1080p50） |
| 录入声道 | 选择写入文件左/右两路的源声道，通常选 1 / 2；多声道源可选 3 / 4 等；单声道源复制到左右 |
| 参考电平换算 | H.264 默认按 NDI SMPTE 参考电平 -20 dB 换算为文件音频，EBU 可选 -14 dB |
| 延时摄影 | 仅 H.264，无音轨；N 倍快放或每隔 S 秒取一帧 |
| 接收带宽 | 可选最高或最低带宽接收，不会把 Full NDI 转成 HX |

注意事项：

- **自动编码器**按 NVENC → QSV → AMF → Media Foundation 逐项实际试编码；列表中出现不代表本机具备该硬件，失败会显示原因。
- **FFV1 无损**保存 NDI SDK 解码后的像素与浮点音频，不代表 NDI 传输前的原始信息；该模式禁用尺寸、帧率和延时摄影调整，不施加录制增益，并生成 `.checksums.json` 校验摘要。
- **延时摄影**：N 倍表示实录 N 秒对应成片约 1 秒；「每隔 S 秒取一帧」在播放帧率 F 时，实录 S × F 秒对应成片约 1 秒。成片时长受帧取整影响。
- 通道参数的修改**用于后续任务**；正在运行的任务保持启动时的参数快照。
- **「恢复默认参数」**把表单中的录制参数恢复为基础设置里的新通道默认值，保留通道名称、NDI 来源和计划；点击保存后生效，取消则放弃。

## 5. 计划录制与时间轴

### 创建与编辑计划

- 通过每路 **「计划…」** 按钮新建计划；在时间轴上**双击**计划色块精确编辑。
- 新计划的分钟、秒默认填 00，可用「今天 / 明天 / 下个整点」快捷开始时间和「1 / 2 / 4 小时」快捷时长；编辑已有计划不自动取整。
- 「计划…」菜单也能编辑已停用或当前视图之外的计划；「计划启用」复选框控制整路的计划执行。

### 计划类型与规则

- 支持**指定日期一次、每天、每周指定星期**。时区固定为中国标准时间 UTC+8。
- 结束时间不晚于开始时间时自动跨到次日；起止相同表示 24 小时。超过一天的持续收录请使用每日计划。
- 同一路**重叠**的计划不能保存，相邻区块可以。
- 修改重复计划影响整个系列；「跳过填写日期的这一轮」只跳过一次；停用计划显示为灰色。
- 计划开始前约 5 秒预热接收器。程序重启后，仍在时间范围内的计划从当前时刻继续，错过时段记为 missed（灰色）；未运行期间无法补录，历史回补登记范围最多 90 天。

### 立即录制与手动需求

「立即录制」添加一路手动需求，「结束手动」仅取消手动需求；若此时仍有有效计划，该路继续录制。要停止当前计划，请在计划弹窗中跳过今天或停用该计划。

### 时间轴操作

- 上半部为计划、下半部为实际记录，两段紧贴，带半透明状态色、点阵背景和淡日期水印。
- **左键拖动**平移视图；**滚轮**在悬停位置缩放（范围 1 分钟至 14 天）；底部「时间导航」滑块左右浏览；「小时 / 日 / 周」切换视图，「跳转」跳到指定日期。
- **自动跟随**默认开启，当前时刻（红色竖线）保持在可视范围约 1/6 处；任何手动浏览都会暂停跟随，点击「回到现在」或重新勾选恢复。
- 每个实际录像文件的起点用浅色短虚线标记；双击有文件的历史区块打开文件；「录制历史」提供分页列表、播放和打开目录。
- 状态配色：蓝=计划、红=录制、绿=完成、琥珀=信号缺失、紫=失败/中断、青=已恢复、灰=停用/错过。悬停色块查看详情。

## 6. 音频：录制增益与监听

两者互相独立：**录制增益改变文件音频，监听音量只改变本机播放响度**。

### 录制增益

- 每路「音频」弹窗提供 -24～+24 dB 实时调整，0 dB 表示不额外增益，+6 dB 约为两倍振幅。
- 调整实时生效（经过现有缓冲），不重启工作进程；松开滑块或点击增减按钮时保存到通道配置，用于下次录制。
- 增益叠加在 NDI 参考电平换算之上。FFV1 无损模式与无音轨的延时摄影**禁用**该增益。
- H.264 下增益过大可能削波，请留意电平红区。

### 监听与监听音量

- 「监听」播放该路声音，同时仅一路，默认静音；再次点击「静音」停止监听。监听中的按钮显示绿色，底部可一键「取消全部监听」。
- 监听跟随所选声道对及录制增益；录制期间跟随当前任务的源和参数快照，修改通道设置在任务结束后才用于预览。
- 底部「监听音量」提供 0～400% 滑块、±25% 按钮与 100% 恢复按钮，并显示正在监听的通道；0% 为静音，调节后保存。
- 无损监听保留原始增益，但声卡输出会限幅。预览电平包含参考换算和录制增益，不包含监听音量；它不是响度或 True Peak 测量。

## 7. 录制文件与历史

- 文件按 `存储路径/通道名/日期/` 组织，成功结束后文件名为 `开始时间-结束时间_任务标识_段号.mp4`（如 `20261002_080000-20261002_090000_任务标识_1.mp4`），跨午夜也可辨识；无损为 `.mkv`。
- 写入中的文件名含 `_recording_`，封装成功后自动改名并更新录制历史；异常退出或文件被占用无法改名时**保留原名，绝不删除录像**。
- MP4 使用碎片化封装：首个完整片段写出前的异常退出仍可能留下无法恢复的文件，请使用兼容碎片化 MP4 的播放器/剪辑软件。
- 开录时尚无视频：程序等待真实首帧并记录未录到的时间区间，不假定输入规格、不制造占位文件；等待期间可取消，计划到时自动结束。
- 已取得规格后，视频缺失时补黑帧、音频缺失时补静音，两条信号分别处理；恢复后继续写入，历史和日志标记缺失区间。源规格变化时结束当前工作进程并有限重启，使用新片段继续。
- 连续失败最多自动重试 3 次（2/4/8 秒退避），再次失败需人工恢复；连续正常录制 30 秒或正常结束后重置失败次数。

## 8. 监测与诊断

### 实时监测

- 每路「监测」查看本次任务的分类统计，**不新增接收器、不播放声音**：SDK 视频/音频丢弃、接收队列视频/音频溢出、处理缓存溢出、场配对失败分别计数；重复画面、黑画面和静音填充单独列出。
- 默认显示**最近 60 秒**滚动窗口（启动不足时按实际覆盖秒数）；勾选「查看任务累计」保留整个任务统计。录制历史中的「监测」显示同一任务全部分段的汇总；重试属于新任务，计数重新开始。
- 文件 I/O 字节直接读取 FFmpeg 计数，每秒采样，显示近 5 秒、任务平均、采样峰值与累计字节（MB = 1,000,000 字节）。受编码缓存和分段封装影响，短时间可能显示 0 或突增；这不是物理磁盘落盘速度。
- 计数口径：帧率转换/延时摄影的正常选帧不列为故障丢帧；发送端未发出的帧和网络传输中的丢失无法由接收队列完整推断。历史快照由主进程约每 5 秒保存，异常终止只保留最后成功快照并标为部分统计。

### 24 小时现场诊断

1. 完整解压发布包，先退出旧版程序，双击 **`Start-24h-Debug.cmd`**，再按平常方式配置来源与计划。
2. 脚本每 30 秒采样进程 CPU、内存、句柄、线程、I/O 和磁盘剩余空间，每 10 分钟在线备份数据库及日志，工作进程每分钟记录接收时效、时钟偏差和各阶段统计。不额外接收 NDI，也不逐帧分析画面。
3. 运行至少 24 小时后，建议先在程序里停止录制让文件完成封装，再在诊断窗口按 **Enter** 或双击 **`Stop-24h-Debug.cmd`**。停止诊断不会停止录制。
4. 脚本不会在 24 小时自动结束（最长 30 天）；采样流式写入，日志副本上限 256 MiB。

### 离线录像检查

双击 **`Inspect-Recording.cmd`** 选择已结束录制的文件（可多选），完整解码检查黑场（至少 2 秒且至少 98% 像素低于阈值）、静音（低于 -50 dB 至少 2 秒）、格式信息和解码错误。该扫描消耗 CPU/磁盘，建议停录后运行。节目自身的黑场和静音也会被检出，需结合运行日志判断。

反馈问题时，把 `diagnostics/run-*` 和 `diagnostics/video-check-*` 两类目录完整提供即可；报告不含录像，也不自动上传。

## 9. 基础设置

- **录像根目录、安全余量**（默认 10 GB）：新任务按当前存储设置检查空间；运行中的任务按启动时的路径和余量自行检查。低于余量时停止受影响录制，**不自动删除文件**，空间恢复后点击「恢复任务」。
- **预览帧率、额外发现 IP、日志保留、登录自启**。
- **新通道默认参数**：新建通道的默认录制参数；「恢复默认参数」以此为准，已有通道不自动覆盖。
- **软件缩放**：见下节。

## 10. 配置导出导入与升级

- **导出**前显示说明：包含基础设置、来源和通道参数、计划日期与重复/跳过规则；**不包含**录像、历史、统计、日志或临时监听状态。
- **导入**先读取并检查 JSON，默认不选择任何内容。勾选计划时自动带入其必要通道，也可仅选通道；基础设置需单独勾选。点击「检查所选」再确认合并：保留未涉及的现有通道和计划；同标识且内容一致的跳过；内容不同或时间重叠会阻止导入，不做静默覆盖。
- 录制中可以预览导入内容，但不能应用。导入前请停止全部录制，并保留原导出文件便于回退。

## 11. 高 DPI 与缩放恢复

- 程序使用 Per-Monitor V2：窗口跨屏时按当前屏幕 DPI 重绘文字和控件，工作区改变后收回可见区域。
- 「基础设置 → 软件缩放」提供 80% / 90% / 100% / 110% / 125% / 150%，叠加在 Windows 系统缩放之上；100% 即跟随系统。修改立即预览，保存持久化，取消恢复原值。
- 界面放大后无法操作时的恢复方法（任选其一）：
  - 按 **Ctrl+0**（主键盘或数字键盘 0 均可，设置弹窗打开时也有效）；
  - 按住 **Shift** 启动程序；
  - 执行 `ndi-recorder.exe --reset-ui-scale`（程序已运行时会通知已有窗口恢复）。
- 恢复的只是软件倍率，Windows 自身的 DPI 缩放不受影响。

## 12. 托盘与单实例

- 关闭窗口后程序驻留系统托盘：**双击**托盘图标恢复窗口，**右键**菜单打开或退出。
- 重复启动只会激活已有窗口（单实例）。
- 软件仅运行在用户登录会话中；主动睡眠、关机或注销会中断录制，不支持作为 Windows 服务运行。

## 13. 故障排除

| 现象 | 排查建议 |
|---|---|
| 找不到 NDI 源 | 在「基础设置」添加发送端 IP 后重新发现；确认两端网络可达、NDI 版本兼容 |
| 无法操作放大的界面 | Ctrl+0 恢复 100% 缩放，或按住 Shift 启动 |
| 录制自动停止并报磁盘空间 | 检查录像盘剩余空间与安全余量；空间恢复后点「恢复任务」 |
| 文件保留 `_recording_` 名称 | 封装未完成或文件被占用；关闭占用程序后可人工改名，文件本身不丢 |
| 隔行源画质疑问 | 确认帧率设置为 0（双场去隔行），输出为 1080p50 |
| 音画同步疑问 | 用「监测」查看丢帧计数，用 `Inspect-Recording.cmd` 离线检查黑场/静音区间，并保留 `diagnostics/` 目录 |
| 现场偶发黑场 | 使用 24 小时诊断采集日志后再分析，不要仅凭计数认定网络或编码器故障 |

更多技术口径（计数定义、缓冲上限、恢复策略）见 [ARCHITECTURE.md](ARCHITECTURE.md) 与根目录 README。
